## 6. 判定与改进方向

**按模板退出条件：两项指标均不达标 → 该配置（大型异构仓库）下产品不可用于试点定位。**

失败可归因到三个具体机制（按误报消除收益排序）：

1. **parentKey 空值比较伪变化**（贡献 12/13 误报）：`featureBehaviorChanged` 对 parentKey 用严格 `!==`，AI 输出树（undefined）与落库树（null）表示不一致即判身份变化。**已于报告当日修复**（`?? null` 归一化 + 摘要整段重写的兜底折叠 + 锚定提示词补简介沿用规则）；用存储树重放 v40→v41，12 条伪变化全部消失，精确率 6/19 → **6/7 = 85.7%**（剩余 1 条误报即模式 B）。
2. **测试/文档证据可驱动「新增功能」**（修复后 1/7，性质最重）：#1009 的场景证据直接是 test 文件。**残余已闭合（当日二次修复）**：分析期对 patch 做注释/空白行扫描（`lib/patch-scan.ts`，确定性状态机，保守方向），`release_files.behavioral_change` 标志落库（migration 038），门禁升级为**证伪语义**——仅当功能的实现证据主张全部被证伪（仅注释变动或不在本发布行为变更集）才折叠为 tests-only。#1009 实例已折叠；「查看者宽松模式」（证据全为文档但实现真实存在）被正确保留。**取代 3f77f9b 的分级预折叠**：纯测试/文档证据、无可证伪实现主张的功能保留可见而非静默吞掉——宽松模式教训（错折叠真功能 > 多留一条噪音）。重放口径精确率 6/6 = 100%（历史 run 原值 31.6% 保留为对照）。
3. **快照覆盖上限**（贡献 5 条召回未中）：160KB 采样对超大仓库只覆盖 12 特性。短期修复方向不是扩采样，而是**覆盖披露**：规格页/导出应声明「本规格基于 N 个源文件采样，仓库共 M 个源文件，覆盖率 P%」——把「没看到」从隐性缺陷变成显式边界。这与数据说明页的诚实定位一脉相承。

**对 dogfooding 数据的回溯校验**：自家仓库锚定后「5 提交 = 2 条真变化」的良好表现**不可外推**——本次第三方数据暴露了两个自家仓库恰好未触发的噪音模式（parentKey 空值伪变化、tests-only 功能提交）。WorkBuddy 的「自家仓库自证漏洞」警告成立。
