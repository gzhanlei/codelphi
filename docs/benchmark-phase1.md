# CoDelphi 仓库分析 Benchmark Phase 1 规格（v1.0）

> 日期：2026-11-10
> 来源：ChatGPT benchmark v1.0 提案（2026-11-10）+ 仓库现状对账（§1）。提案大半内容已有对等实现，本文件只收编真正的增量，按 solo 可持续的标注成本收缩范围。
> 基线：`analysis-pipeline.md`（管线全貌与既有指标）、`pilot-blind-eval-superset-rerun-2026-11-10.md`（判定口径先例）、`pilot-acceptance-template.md`（对外试点口径，**本规格不修改它**，其扩展走工单 BM-3）、`specsight-gap-improvement-plan.md` §11（工单簿）。
> 状态：Phase 1 范围已裁决。**首轮全部指标为基线测量；验收硬线在基线数据产出后冻结**——在没有任何增量模式实测数字之前先承诺 ≤2% 的线，是提案的顺序错误，本规格予以修正。
> 定位：本文件是评测规格，不改管线代码。能力结论以盲评报告与完整性账本实测为准。

## 0. 总原则

1. 测真实仓库与真实变更，不只测构造 Demo 与初次全量。
2. Ground truth 由人工预标冻结；LLM 输出（含异构模型）只作初筛/交叉核对，不作标准答案。
3. 召回与精确分开；未分析 ≠ 无变化；任何比率必须有显式分母。
4. 质量、覆盖、成本、完整性分列报告，不合并总分。
5. 两验收面：能力（发现/描述/证据正确）与可信度（知道自己看到什么、没看到什么）分开，后者是产品差异化。
6. 【修正提案】全仓库功能穷举标注不可行 → 采用**两级标注制**（§3）。
7. 【修正提案】S4–S6 超大仓库测试冻结（§7）——superset 2149 实现文件装配率 1.15% 已是披露事实，Linux 级仓库的分析答案已知（partial + 近零覆盖 + 诚实披露），跑一次不产生新信息。
8. 增量正确性是第一优先指标组：最危险的失败是错误地认定某功能不需要分析（既有红线）。
9. 静态不可见边界（运行时 flag、数据依赖行为）沿用指标 2b 盲区披露口径，不进及格线。
10. 每轮 benchmark run 必须附 R1 完整性账本快照；报告中 `complete` 声明仅在账本六维度全绿时允许作出。

## 2. 规模分层与统计口径

采纳 S0–S3 四档（S4–S6 冻结见原则 7）：

| 档位 | 实现文件数 | Phase 1 角色 |
|---|---|---|
| S0 | 50–200 | 候补（现有五仓复测已覆盖量级） |
| S1 | 200–500 | 跨语言泛化仓目标档 |
| S2 | 500–2,000 | 候选 |
| S3 | 2,000–5,000 | superset（实测 2,149 实现文件）已入库 |

统计口径统一以 `scripts/measure-first-analysis.ts` 的 evidenceKind 实现面口径为准（实现文件数与字节，排除测试/文档/生成/静态资源），不用仓库总文件数当分母。入库快照须记录：实现文件数/字节、仓库总文件数、`.git` 尺寸、代码行数、语言分布、冻结 commit SHA。

规模与难度非线性（耦合的业务文件难于独立的生成文件）：档位只用于分组报告与验收线分级，不用于预测成本。

## 3. Ground Truth：两级标注制

### 3.1 L1 窗口级行为预标（既有模式，先例已冻结）

字段：预标 ID、行为变化描述、证据（commit · 文件）、跨文件标记、**重要程度（core / normal / internal，新增）**。先例：`docs/benchmark/frozen/superset-2026-11-08/recall-labels.md`（15 条 + 2 条盲区样本；2026-11-10 已从 `/tmp/superset-pilot/` 抢救入库，含 19 个冻结窗口 patch 与 index-patch）。

### 3.2 L2 核心功能清单（新口径）

每仓库人工标定 30–80 条 must-know 核心功能（名称 + 入口 + 所属模块），用于**核心功能召回**口径，替代提案的全仓库 Feature Recall（穷举标注不可行）。大仓库可用抽样模块估算，估算口径须随报告披露。

### 3.3 判定口径三分（采纳提案）

发现正确性（该分析的功 analysis 是否被覆盖）、描述正确性（C/A/O 是否与代码行为一致）、证据正确性（证据是否真实支持该描述且指向正确版本）**分开计分，不混成一个分数**。

### 3.4 冻结纪律

- 预标冻结**早于**首次目标运行；冻结件入库 `docs/benchmark/frozen/<repo>-<date>/`，不再放 `/tmp`（本次抢救即为教训）。
- solo 判定允许，但须照 rerun 报告 §1 声明独立性折扣 + 异构模型初筛 + 机械化证据审计三重缓解。
- 拿不准的条目归入 unknown 区并披露，不计入分母（预标不确定性不得污染指标）。

## 4. 指标与验收线

### 4.1 行为识别（L1 口径，既有）

窗口召回 / 功能级精确，沿用四跑口径与冻结预标；验收线 ≥80% / 误报 <10% 沿用模板。

### 4.2 核心功能召回（L2 口径，新）

首轮 = 基线测量，线后冻结。分仓库/分档位报告，多仓库 Macro Average（先按仓算再平均，防大仓样本量掩盖小仓失败）。

### 4.3 增量正确性（新，定义见 §6，第一优先）

| 指标 | 定义 | 首轮 | 线（基线后冻结，提案线供参照） |
|---|---|---|---|
| Affected Feature Recall (AFR) | 预标 affected 中被判定受影响且完成重提取的比例 | 基线 | ≥90% |
| Unaffected Preservation (UP) | 预标 unaffected-confirmed 中新版本逐字沿用（措辞锚定成立）的比例 | 基线 | ≥95% |
| False Unaffected Rate (FUR) | 实际受影响却被静默判定 unaffected 的比例 | 基线 | ≤2%，**静默 = 0 容忍硬门禁**：必须显式重提取或显式 unknown，不允许无痕迹跳过 |
| New Feature Recall (NFR) | 预标 new 中被识别为新功能/新场景的比例 | 基线 | ≥85% |
| Stale Evidence | 沿用证据在新 HEAD 下路径失效或内容不再支持描述 | 基线 | 0% |

**Stale 语义修正（append-only）**：沿用证据指向被继承版本 commit 是设计如此，不算 stale；只有路径在新 HEAD 不存在、或行内容已不再支持描述才算。检出靠 §5 证据版本案例；行号重锚定本身是已列 P1 方向，benchmark 测「失效可被检出」，不测「重锚定已实现」。

### 4.4 证据质量

| 指标 | 口径 | 线 |
|---|---|---|
| Evidence Traceability | commit+文件+行可定位 | 100%（`assertEvidence` + 清洗硬门禁已在位，benchmark 实测核验） |
| Evidence Validity | 证据在允许集内且真实存在 | ≥98% |
| Evidence Support | 证据内容确实支持该行为描述（人工判定，新） | 基线后冻结；提案线 ≥95% 供参照 |
| 措辞锚定噪音 | 未变场景被改写的条数 | 计入精确率扣分项（UP 的展示面） |

### 4.5 完整性披露

每 benchmark run 附 R1 账本快照（六维度 + overall）；报告须如实呈现 partial 维度及原因，与分析结论并列。

### 4.6 成本与性能

每 run 记录：LLM 输入/输出 token（含缓存命中拆分）、调用数、重试数、总成本（`LLM_PRICES` 两档口径）、P50/P95 耗时。1 SAU 是定价不是成本预算——毛利结论走工单 R5 看板，benchmark 只如实记账。

## 5. 变更案例矩阵（Phase 1 裁剪版）

载体仓库优先 superset（预标纪律已跑通、四跑可比）。每案例 ≥2 次运行（单 run $0.07–0.19，成本可忽略），模型/prompt/参数版本冻结记录。

| # | 类型 | 案例数 | 预期结果 / 验收口径 |
|---|---|---|---|
| 1 | 单文件局部修改 | 2 | 召回该行为，无虚报 |
| 2 | 多文件同功能 | 2 | 合并为同一功能，不拆裂 |
| 3 | 新增功能 | 2 | NFR 口径 |
| 4 | 删除功能 | 2 | 旧规格不得保留已删行为（删除检测已知偏弱，首轮测基线） |
| 5 | **共享依赖修改** | 2 | **不要求全识别**（跨文件调用图未实现，管线文档 §2 已列 P1）。验收 = W0-10 契约③：未归属行为文件显式列出 + 不静默 + 报告 unknown。测的是「披露诚实」不是「全知」 |
| 6 | 数据模型/配置 | 2 | 有代码 diff 部分按行为变化处理；纯运行时翻转走 2b 盲区披露 |
| 7 | **纯重构（含改名/移动）** | 2 | 0 行为变化虚报（parentKey 旧伤常驻回归）；文件移动后旧证据失效**可被检出**（§4.3 Stale） |
| 8 | 纯注释/格式 | 1 | patch-scan 判非行为 → 0 虚报 |

权重说明：#7/#8 是「不虚报」回归（精确率防线，历史上有实伤）；#5 是「显式披露」检验（诚实度防线）；两者优先级高于召回增量。#5/#6 的共享依赖与配置面在调用图落地后升级为识别率指标，届时重开。

## 6. 增量盲评专项设计（第一优先，工单 BM-1）

### 6.1 为什么

四跑盲评全部实际执行为 full 模式（预标窗口与 v40 索引零交集 → 受影响集为空 → 保守回退全量，原 11-08 盲评经 push 管线但同样回退）。carry-forward、W0-10 三类输出契约、affected/unaffected 判定**零 ground truth 检验**；W0-6「增量召回 ≥80%」闸门至今虚设（任何窗口都解析成 full，永远达不到被检验状态）。

### 6.2 窗口构造

前置条件：目标仓库存在已落库 spec 版本 V_prev，且候选窗口 diff 与其 `spec_file_index` 证据面有交集（patch-scan 行为文件能命中既有功能）。两条路径：

- **自然路径**：等待 superset upstream 新 push（不可控，作机会窗口）。
- **受控路径（首选）**：以已分析版本为基线，从 git 历史选取紧随基线 commit、且与基线证据面有交集的真实 commit 窗口，走 webhook 或 `queueAnalysis(repoId, beforeSha, afterSha)` 执行真增量。

### 6.3 三清单预标 + unknown 区

对窗口内每个既有功能预标：

| 清单 | 定义 | 判定基准 |
|---|---|---|
| affected | 该窗口行为变化应波及、需重提取的功能 | 预标依据文件 + 变化传导理由 |
| unaffected-confirmed | 确定未受影响、应原样沿用 | 新版本逐字沿用 = 判定通过（措辞锚定使其可机械化核验）；被改写/删除 = 候选误伤 |
| new | 窗口内新增功能/入口 | 应被三类契约②捕获 |

### 6.4 判定与产出

逐功能比对 V_prev → V_new；输出 §4.3 四指标 + Stale 检出情况 + **静默 unaffected 案例清单**（有则直接生成 P0 工单——这是本专项存在的核心理由）。

## 7. 仓库集（Phase 1）

- **已入库**：apache/superset（S3，Python/TS，预标与冻结件复用，四跑可比）。
- **待选 1 个 S1–S2 非 Python/TS 仓**：条件 = 持续开发、业务行为可识别、license 允许、非作者仓库。初选候选 gin-gonic/gin（Go）量级类似仓；**选定前置动作 = 实现面分类器与 patch-scan 在该语言上的判定抽查**（C 系/静态语言从未验证，语言支持是独立前置，不是本规格范围）。
- **明确不进**：Linux / Firefox / PostgreSQL / VS Code（S4+ 冻结；C 系未验证；触发解冻条件 = 真实大仓库客户出现 + 分类器语言支持落地）。

## 8. 执行流程

1. 冻结仓库快照（commit SHA + §2 统计口径入库）。
2. 人工预标（L1/L2/三清单）并冻结入库。
3. Full analysis 基线（L1/L2 指标）。
4. Incremental 专项（§6）。
5. 变更矩阵逐案例执行（§5，每案例 ≥2 次）。
6. 人工复核 + 指标计算 + 报告（§9）。

模型/prompt/参数版本逐 run 冻结记录；模型或 prompt 升级时重跑核心回归集（增量专项 + 矩阵 #5/#7/#8）；原始输出、运行日志、token、配置、人工判定全部随报告归档。

## 9. 报告格式

固定骨架：仓库与案例清单 → 六组结果（§4.1–4.6）→ **分仓库/分变更类型分项 + Macro Average** → FP/FN 具体案例 → Failure Gallery → 与上一版本的变化 → R1 账本快照与覆盖率回执数字（原样引用，不重算）。

Failure Gallery 每条失败记录：仓库、commit、预期、实际输出、根因、修复版本。**第一件展品即现有四跑盲评报告**（L8/L15 残余 → 直接生成 W0-8/W0-9 与 R1–R6 工单，即该格式的实证价值）。

## 10. 非目标与边界

1. 不建 benchmark 平台：预标 markdown + 指标脚本 + 报告 markdown，与现有盲评基建同构。
2. S4–S6 冻结（原则 7）；全仓库功能穷举标注不做（两级标注制替代）。
3. M9 影子对比不是召回证明（管线文档 §7 口径警示沿用）；LLM 输出不当 ground truth。
4. 不修改 `pilot-acceptance-template.md`——其 Evidence Support / 重要程度字段扩展走工单 BM-3。
5. 静态不可见边界沿用 `/data-notice` 与指标 2b 披露口径，不进及格线。
6. 本规格不修改管线代码；指标实现所需的管线侧改动（如有）走工单簿，不在 benchmark 执行中夹带。
