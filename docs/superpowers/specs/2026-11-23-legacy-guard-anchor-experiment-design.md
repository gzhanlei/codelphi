# Legacy GUARD 行为锚点独立实验设计

日期：2026-11-23
状态：实验设计待书面审阅；不授权实施、生产启用或部署

## 1. 目标与实验性质

在不增加完成同等分析任务所需 LLM 调用、总 token 和实际模型费用的前提下，验证少量高信号 GUARD 锚点能否帮助模型注意已经存在于上下文中、但容易被忽略的行为守卫。

首个探针为 CB-18：`lib/analysis.ts` 的 `assertLatestRun` 防止旧 run 覆盖新 run 的激活规格。既有零 AI 分区探针已确认该函数在 L 的输入窗口内，因此 CB-18 是语义显著性问题的候选，不是源码漏读问题。

本实验是独立、预算受限、可证伪的优化实验，不是全量分析管线的新机制。任何通过都只代表允许评估下一阶段，不代表生产采用。

## 2. 核心假设与边界

核心假设：CB-18 是低显著性代码结构被模型遗漏，而不是模型缺乏理解该代码的能力。

职责边界：

- 确定性工具只识别代码结构；
- AI 理解行为关系并归纳产品行为；
- 原有证据机制验证证据真实性；
- 锚点不成为新的行为事实来源，不直接生成场景、规格或 Behavior Delta；
- 锚点缺失不改变原有源码范围、分析范围或输出；
- 原始源码仍是 AI 的必要输入，证据必须指向原始源码而非锚点自身；
- 证据 allowSet 不扩大，人工规格和人工裁决不被覆盖。

首版只实现明确的 `if / throw` GUARD 提取，不处理 `return` 错误、正向激活条件、跨文件守卫或通用调用关系。该规则具有偏向性；没有提取到锚点绝不表示没有重要行为。

## 3. 最小锚点契约

示例：

```text
GUARD lib/analysis.ts:62-66
function: assertLatestRun
condition: latestRunId !== run.id
outcome: throw Analysis superseded
extraction: complete
```

`extraction` 只描述结构提取完整度：

- `complete`：函数、条件、throw 结果和源码位置均在支持范围内完整提取；
- `partial`：任一所需结构无法确认，保留已知部分，不猜测其余内容。

不使用 `resolution: resolved`，避免把语法提取误读为业务含义已确认。锚点数量保持少量，排序和选择规则在查看任何候选输出前冻结；不得根据输出反向调整规则。

## 4. 四组对照

| 组别 | Prompt | 目的 |
| --- | --- | --- |
| A · Baseline | 原始 Prompt，无压缩、无锚点 | 测量原始质量与成本 |
| B · Compression | 只压缩通用指令 | 验证压缩本身是否损害质量 |
| C · Anchors | 原始 Prompt + GUARD 锚点，不压缩 | 隔离锚点的实际收益与 token 增幅 |
| D · Combined | 压缩通用指令 + GUARD 锚点 | 验证预算内替换能否保持收益 |

四组固定相同 commit、源码分区、输入证据、模型版本、模型参数和输出 Schema。Prompt 压缩文本与锚点输出在任何 B/C/D 调用前冻结，不允许看到输出后继续调词。

每组对 CB-18 重复运行 3 次，保存全部 12 次调用的原始输出和真实 usage，不挑选成功样本。重复只用于初步证伪，不能把 3 次命中解释为长期稳定性证明。

## 5. 独立 Ground Truth

- CB-18 的正确行为关系由未参与锚点实现的独立评审从源码确认，不得根据锚点内容反写答案。
- 其余有效真值用于测量非锚点行为和整体召回；CB-34 已判定真值与实现不符，明确排除。
- 既有 AI 冻结标签只作为待评审候选；没有独立确认的标签不得用于通过判定。
- 分别报告锚点行为召回、非锚点行为召回、整体召回、虚假行为和虚假 Behavior Delta，不用 CB-18 单点命中代替整体质量。

## 6. 成本口径

成本按完成同等分析任务的全部调用计算，包括主调用、repair、重试以及供应商单独计费的推理 token。不能只证明主调用次数不变。

硬约束：

```text
D.totalLlmCalls <= A.totalLlmCalls
D.inputTokens + D.outputTokens <= A.inputTokens + A.outputTokens
D.actualCost <= A.actualCost
```

各指标按同组 3 次调用的合计计算。实际费用使用真实回执和相同定价口径计算，涵盖输入、输出、缓存读取/写入及供应商单独计费项目。缓存条件或定价不可比、usage 缺失、隐藏费用无法核定时判 inconclusive，不得按零成本放行。

B 和 C 是诊断臂，分别记录压缩节省与锚点增量；只有 D 承担预算内替换的采用门禁。若 D 的质量收益只能依靠增加 token 或费用获得，则实验失败。

## 7. 质量与可靠性门禁

至少满足：

- C 的 CB-18 命中次数高于 A，证明锚点本身具有可观察收益；若 A 已全部命中，则没有可证明的改进空间；
- B 相对 A 的非锚点行为召回与整体召回不得下降，证明压缩本身没有造成质量回退；
- D 的 CB-18 命中次数不低于 C 且高于 B，排除收益只来自压缩的可能；
- CB-18 场景完整表达“只有最新 run 可激活规格，旧 run 不覆盖新 run 的结果”，并引用真实源码证据；
- D 相对 A 的非锚点行为召回不得下降，整体召回不得下降；
- 虚假行为数量与虚假 Behavior Delta 不得增加；
- 证据 allowSet 完全不变，人工规格不被覆盖；
- D 满足全部调用、总 token 和实际费用约束；
- 独立评审确认真值与结果，未确认部分判 inconclusive。

任一确定失败即关闭候选；证据不足或成本不可比则判 inconclusive，不进入推广评审。

## 8. 实施与退出顺序

1. 为最小 `if / throw` GUARD 提取写 RED→GREEN 测试，覆盖结构完整、partial、非 throw 不提取、锚点缺失不改变原输出；
2. 冻结四组 Prompt、真值、运行配置和判定脚本；
3. 执行 A/B/C/D 各 3 次 CB-18 对照调用；
4. 先评估 B/C 的独立作用，再评估 D 的整体质量与真实账单；
5. 只有质量收益和成本约束同时成立，才另立更大有效真值集的验证计划；否则关闭候选，不增加提取规则。

不建设新的事实表、跨文件依赖、通用代码事实提取管线或生产开关，不执行生产部署。
