# 功能语义流程图设计

- 日期：2026-11-12
- 状态：待书面评审
- 关联：W-DECISION v1.3、RepoMap「固定性能门槛」流程图走查

## 1. 背景与问题

当前流程图已经完成 React Flow + ELK 的呈现层迁移，但图语义仍由 `lib/feature-flow.ts` 中的场景分组和 `step` 字段直接推导。未归属分支与未编号场景会统一连接到 START，导致：

1. 一个入口出现大量平行路径，看起来像不合理的程序设计。
2. 执行步骤、错误处理、历史决策和文档说明混在同一运行图中。
3. ELK 只计算节点位置，React Flow 另行连线与放置标签，仍可能穿节点、穿文字。
4. 没有可靠主链时，入口扇出把“场景清单”伪装成“流程图”。

RepoMap「固定性能门槛」是基准反例：38 条场景同时包含预热、测量、汇总、门槛评估，以及 MALLOC_ARENA_MAX、历史 CI 测量和 investigation 文档说明。目标不是把这些卡片排得更整齐，而是恢复有证据的执行路径。

## 2. 目标与非目标

### 目标

- 默认展示一条可辨认的主执行路径，判断、错误、重试和终态挂在正确步骤上。
- 一个语义节点可以聚合多条场景；节点和边都能追溯到原始场景及代码证据。
- 说明性、重复或无法支持图关系的场景不进入主图，但可在详情中查看。
- 没有有效图时显示场景清单，不再用 START 扇出制造流程。
- 使用自动布局同时解决节点、连线和边标签的碰撞及文字裁切。

### 非目标

- 不改变 `source = 'manual'` 的功能、场景或人工合并优先级。
- 不把流程节点、边或顺序纳入行为变更判定面。
- 不直接推断各编程语言的源码控制流，不新增语言专用解析器。
- 不做流程图自由编辑，不要求所有历史功能一次性回填。
- 不在没有终态证据时添加 END，不为提高连线率而补造关系。

## 3. 方案选择

采用“**AI 生成候选语义图 + 确定性证据与图结构校验 + 版本化持久化**”。场景仍是事实来源，语义图是派生读模型。

不采用：

- 关键词过滤：不同仓库和语言下容易误删真实步骤。
- 直接源码控制流分析：精度和可解释性较好，但语言与框架适配成本远超本批次。
- 页面打开时实时生成：首屏延迟、成本和写操作时机不可控，且重复结果不稳定。

## 4. 图数据契约

每个功能对应一个可选的 `FeatureFlowGraph`：

```ts
type FlowScenarioReference = string;

type SemanticFlowNode = {
  id: string;
  kind: "start" | "action" | "decision" | "error" | "external" | "waiting" | "end";
  title: string;
  scenarioRefs: FlowScenarioReference[];
};

type SemanticFlowEdge = {
  id: string;
  from: string;
  to: string;
  kind: "sequence" | "branch" | "retry";
  label?: string;
  scenarioRefs: FlowScenarioReference[];
};

type ExcludedScenario = {
  reference: FlowScenarioReference;
  reason: "documentary" | "duplicate" | "unsupported" | "out-of-scope";
};

type FeatureFlowGraph = {
  entryNodeIds: string[];
  nodes: SemanticFlowNode[];
  edges: SemanticFlowEdge[];
  excludedScenarios: ExcludedScenario[];
};
```

约束：

- 节点标题是用户可理解的语义动作，不直接堆砌 Context / Action / Outcome。
- 一个节点的 `scenarioRefs` 可以有多项，实现 Specsight 式场景聚合。
- 只有合成 START 节点允许空引用；其他节点必须有至少一个有效场景引用。
- 每条边必须有至少一个有效场景引用，关系证据通过场景关联到代码。
- `retry` 只能用于有重试、返回上一步或循环证据的边。
- END 必须关联终态场景，不得仅因主链结束而自动合成。

## 5. 确定性校验

新增独立校验层，AI 输出只有通过 Zod 形状校验和以下图校验才可持久化：

1. 节点、边 ID 唯一，端点存在，场景引用属于当前功能。
2. 节点总数不超过 24、边总数不超过 48，独立入口不超过 3 个。
3. 至少存在一条包含两个以上非 START 操作节点的主路径。
4. 所有展示节点均可从声明入口到达；不允许多个无解释孤岛。
5. 只有真正独立的用户入口可以从 START 分叉，禁止“未归属场景默认接 START”。
6. 分支必须有条件或结果语义；错误节点不得无条件挂在 START 后面。
7. `retry` 不得把普通顺序边伪装成循环；除显式 retry 外图应无环。
8. 被排除场景必须带原因；被聚合场景仍保留在节点详情中。
9. 任一规则失败则整图拒绝，不裁剪到“看起来可用”，不静默降级为入口扇出。

校验错误以结构化原因记录，便于评估模型输出质量。

## 6. 生成、持久化与失效

### 6.1 生成时机

- 在功能与场景完成 AI 提取、carry-forward 和人工来源合并后，以**最终场景集合**生成候选图。
- AI 调用发生在数据库事务外，不能延长规格事务或阻塞规格提交。
- 图生成失败不影响功能、场景、差异或发布版本落库，只使该功能的流程图不可用。
- 增量分析只重新生成受影响功能的图；未受影响功能在场景指纹一致时复制上一版图。
- 对存量功能提供显式回填脚本，按功能粒度执行，不在页面 GET 请求中隐式生成。

### 6.2 存储

新增 migration `068_feature_flows.sql` 与 `spec_feature_flows` 表：

- `spec_feature_id`：主键并关联 `spec_features(id)`，级联删除。
- `graph_json`：通过校验的 `FeatureFlowGraph`。
- `scenario_fingerprint`：由最终场景的 reference、category、context、action、outcome、step 和 source 确定性计算。
- `created_at` / `updated_at`：生成与更新时间。

场景指纹只用于判断派生图是否失效，不进入行为差异判定。

### 6.3 失效与人工编辑

- 读取时重新计算最终场景指纹；不一致即返回“流程图待重新生成”，禁止展示旧图。
- 人工新增、修改或删除场景都会使旧图失效，不覆盖人工场景。
- 本批次提供按功能重新生成的服务与脚本；后续批次再考虑页面上的显式重新生成按钮。
- 增量版本的未受影响功能仅在指纹一致时复制图，否则留空并记录原因。

## 7. RepoMap 基准图

「固定性能门槛」的目标主链为：

```text
START
  → 校验构建产物与参数
      ├─ 缺少 dist / 参数非法 → 退出 2
  → 预热
  → 执行 N 次测量
      ├─ 未生成 receipt → 退出 1
      └─ 缺少 /usr/bin/time → 跳过 RSS 检查并继续
  → 汇总测量结果
  → 评估性能门槛
      ├─ 任一指标超限 → FAIL / 退出 1
      └─ 全部通过 → PASS / 退出 0
```

MALLOC_ARENA_MAX、历史 CI 测量、investigation 阅读和堆上限解释归为 `documentary` 或 `duplicate`，保留在关联场景中，不进入运行主图。

此图是验收基准，不允许为了得到该形状而硬编码 RepoMap 专用节点或分支。

## 8. 渲染与交互

- `lib/feature-flow-layout.ts` 改为消费已验证的语义图，不再从场景创建默认入口边。
- ELK 负责节点位置、正交连线和边标签位置；自定义 RoutedEdge 使用返回的 edge sections，不再用 SmoothStep 覆盖 ELK 结果。
- 节点高度根据标题和摘要的实际行数计算，再交给 ELK；禁止用固定高度挤压文本。
- 主路径纵向排列，分支在侧面汇合；回边使用独立通道，不穿过节点或标签。
- 节点详情展示聚合场景的完整 Context / Action / Outcome、分类和代码证据。
- 被排除场景在单独区域展示原因，不与主执行路径混合。
- 保留缩放、拖拽、fitView、详情侧栏和窄屏下方详情。
- 图缺失、指纹失效或校验失败时显示场景清单及明确原因，不回退到旧扇出图。

## 9. 可观测性与成本

- 图生成调用使用独立 `chargeComponent` 和 `callKind`，进入现有 LLM 回执。
- 记录功能、版本、场景数、节点/边数、排除原因、校验失败原因和生成耗时，不记录秘密信息。
- 图生成不参与场景召回、精确率或行为差异计算。
- 额外 AI 调用只针对受影响功能和显式回填项，设置并发与节点上限，避免全量重复调用。

## 10. 测试与验收

### 单元与集成测试

- 图 schema：非法引用、重复 ID、断边、孤岛、过多入口、无证据 END、伪 retry。
- 主链要求：单节点清单、无有效主链、说明性场景占多数时拒绝出图。
- 聚合与排除：重复动作聚合、documentary 场景保留详情但不连入 START。
- 指纹：任一场景内容或来源变化使旧图失效；未变化时增量复制成功。
- 人工来源：人工场景和合并优先级不变，行为 diff 不包含图数据。
- 布局几何：节点不重叠，连线不穿节点，标签文字不被连线穿过，标签之间不碰撞，长文本不裁切。

### 基准与端到端验收

1. RepoMap 链接：`/products/u-a8811be775/repomap?view=spec&feature=9176&mode=flow` 呈现第 7 节主链及对应分支，不出现 START 向说明性场景扇出。
2. Specsight 对照：主路径、判断分支、失败出口和汇合关系可直接辨认，而不是逐场景平铺。
3. 既有「超管手工充值」节点：长标题和 outcome 不裁切，详情证据仍可点击。
4. 既有 26 场景 / 26 情境案例：没有有效语义图时显示清单，不恢复四列 START 扇出。
5. 桌面与 390px 窄屏完成缩放、拖拽、节点详情和关闭操作。
6. 现有 W-DECISION 重放：场景召回 ≥80% 不回退、精确率不回退、FUR=0；图生成失败不影响规格版本。
7. `npm run typecheck`、`npm test`、`npm run build` 全绿后再部署；部署后复测基准链接与容器健康。

## 11. 实施边界与回滚

- 第一批只启用显式回填的功能和后续分析中的受影响功能，不做全库回填。
- 语义图不可用时场景标签页始终可读，作为无图形替代。
- 回滚应用或删除 `spec_feature_flows` 数据均不影响功能与场景；迁移只新增派生表，不修改现有事实表。
- 若模型输出持续不能通过校验，停止扩大启用范围，保留规格与场景能力并重新评估生成策略。
