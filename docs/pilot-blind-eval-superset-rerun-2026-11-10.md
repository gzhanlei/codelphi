## 6. 残余根因与改进方向（与原盲评的本质区别）

**多趟机制本身生效**：装配面从单窗 ~160KB（12 特性 / 26 场景）扩到 126 文件 / 948KB（40 特性 / 129 场景）；原「窗口截断吞掉」的 L6/L10 转为命中；覆盖回执（B1）显式记录 6 分区触顶。

**残余 7 条未中不再「读得窄」为主，而是两层新机制：**

1. **分区装配不保证窗口 diff 文件全量入选**（直接证伪：装配 126 < 窗口 diff 131）。diff 文件是行为变化的一手证据面，却由通用路径评分决定是否入选 → L4（transport.py）/L8（oauth2.py）/L12（create.py）等深层 diff 文件未进分区。改进方向便宜且明确：**装配策略把窗口 diff 文件设为必选，剩余预算按邻接度填充**——L4/L8/L12/L15 的文件全是 diff 文件，此项落地后这些条目从「没读到」变「读到待写」。
2. **读到了但泛化**：语义层文件在分区里（「语义层」功能存在），但 Content-Length 校验行为没被写成场景——选择质量层（首分析改进计划 ①）的问题，不是本计划范围。

**覆盖率事实**：superset 实现面 2149 文件 / 79.9MB，6 分区装配 126 文件 = 1.19%，触顶显式警示在位（B1 落地生效）。按计划红线，该数字不作为放宽门槛的理由。
