# CoDelphi 试点验收模板

日期：2026-11-08
适用：对外试点方案（自托管、单仓库、非核心系统）。本模板是验收口径的唯一定义，报价/续约以本页数字为准。

## 定位声明（验收前先读）

- CoDelphi 的交付语义：**把代码变更翻译成发布说明与回归范围辅助，逐条附代码证据，采纳前经人工核实**。
- 本产品不判断「做对了没有」。验收测的是翻译质量（报得准、报得全），不是正确性仲裁；任何以「CoDelphi 说没问题」为由跳过人工判断的用法都超出交付边界。

## 试点设置

- **仓库要求**：非作者仓库（盲评）；语言/框架与 dogfooding 仓库不同；包含 feature flag 与运行时配置；至少包含 1 个 DB migration。
- **判定人**：不参与该仓库开发、不阅读 CoDelphi 输出以外的分析材料；独立对照源码（及可观测的运行现象）判定每条输出。
- **周期**：4 周。

## 量化指标

| # | 指标 | 口径 | 权重 |
| --- | --- | --- | --- |
| 1 | 精确率 | 抽查 20 条行为变化，判定误报 < 10% | 中 |
| 2 | 召回率 | 人工预标 15 条**静态可观测**的真实行为变化（其中 ≥ 5 条跨文件/跨配置），CoDelphi 报出 ≥ 80% | **最高** |
| 2b | 盲区披露 | 另预标 2 条纯运行时开关导致的变化（零代码 diff），只统计并如实披露报出比例，**不进及格线** | 披露项 |
| 3 | 工时 | 发布说明撰写耗时下降 ≥ 30%；同时记录「人工修正条数」——防止省时来自没人细看 | 中 |

口径说明：

- **召回率限静态可观测**：纯运行时开关变化（零代码 diff）超出静态分析的声明边界，计入及格线会让任何静态分析产品必然失败；此类变化只作为盲区比例披露（指标 2b），与「本产品从静态代码读取行为」的定位一致。
- 指标 1 与 2 都必须满足；只测精确率会奖励「少报」——一个永远只报 1 条的系统精确率 100%、召回率趋近 0。

## 定性闸门（先于一切指标）

试点期间出现 1 次「按 CoDelphi 结论放行、实际行为不符」→ **直接终止**，不进入指标讨论。

## 退出条件

任一量化指标不达标即不续。

## 报告要求

对外报告必须注明：基线数据来源、判定人身份、仓库特征（语言/框架/规模/flag 情况）；否则结论不可复用，视为未验收。

## 已知边界（随报告一并披露）

- 路径守卫只防引用幻觉，不防语义幻觉：真实行号配错误解读照样通过校验；证据覆盖率描述证据范围，不表示结论正确。
- 静态分析不可见 feature flag、灰度开关、运行时配置与权限数据（指标 2b 即其度量）。
- 单仓库粒度：每个产品接一个主仓库，跨仓库的影响传播（如 API 契约变更波及下游服务）不在交付范围内；polyrepo 产品可按服务各建产品空间。
- 判据缺口是结构性的：产品比较的是「上一版规格 vs 这一版规格」，两者都来自代码；意图偏差需要 PRD、契约、测试与遥测等独立判据，本产品不提供。
