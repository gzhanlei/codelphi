## 2. 核心诊断：话术越界是产品契约问题，不只是市场问题

GLM 把我的四条批评（循环论证、证据可溯被偷换、权威感 UI、CTO 摘要名不副实）统一成「产品话术」，比原评审更准。但需分两层看：

- **市场层**：改首页文案即可止损。
- **契约层**：一旦客户按「规格真相源」采购，售后口径、合规举证、事故责任归属都会按那个标准来。订阅制 + Chandler 代收落地后，这是**有对价的承诺**，不是一句低调的文案。首页免责的作用是限定责任范围。

### 「行为账本」仍越界半步

「行为账本，非正确性判据」只从「判据」退到「账本」，但**账本仍暗示记录了真实发生的行为**。而系统里的「行为」是 AI 从静态代码推断的，不是观测到的；真正的行为账本来自线上遥测、埋点与事故记录。建议再退一格：

| 当前表述 | 建议表述 | 理由 |
| --- | --- | --- |
| 可追溯的产品规格 | 代码变更的可读翻译 | 「规格」暗示约束力 |
| 行为账本 | 发布说明与回归范围辅助 | 「账本」暗示观测真实性 |
| 规格可信度（UI 指标） | 证据覆盖率 | 可信度是判断，覆盖率才是事实 |
| CTO 进展摘要 | 30 天变更索引 / 发布变更清单 | 不带角色承诺 |
| 保持所有产品同频 | 让非技术干系人看懂每次发布 | 可度量、不承诺组织效果 |

禁用词（首页、导出命名、定价页、销售物料）：真相源、判据、正确性、规格可信度、保证、以及用角色名命名导出物。

### README 自我警示（可直接贴）

> 路径守卫只防引用幻觉，不防语义幻觉：真实行号配一段错误解读，照样通过校验。Spec 版本号、证据文件数、可点击行号呈现的是证据覆盖率，不是结论正确性。本产品不判断「做对了没有」；人工核实标记是规格生效的前提，不是可省略的兜底。

## 3. 商业契约触发的硬前置：优先级应提到最前

GLM 把企业级清单归到「收钱那刻自动变成真需求」，方向对，但归类偏后。订阅制 + Chandler 代收意味着已有对价，README:182 那句「代码仅发送给配置的 AI 网关；应确保 LLMGateway 及其上游符合内部代码保密要求」就从免责声明变成**必须落进条款的数据处理问题**：

1. 子处理方名单（LLM 网关及其上游）、数据驻留区域
2. 源码是否用于训练、留存时长、删除与撤回机制
3. 事故通知时限与责任上限
4. 定价页 / 服务条款同步（当前 `/pricing` 404，定价文档 V1.3 仍在 `.gitignore` 未入库）

这是首次采购会谈第一个被问到、且唯一可能当场终止的问题，早于 SSO。它也不依赖任何工程改造，可与话术收敛同批完成。

## 4. 修订后的 4 周试点验收

原框架专业，可直接用作对外试点方案模板；但三处必须补强，否则数字会自证。

| # | 指标 | 口径 | 权重 |
| --- | --- | --- | --- |
| 1 | 精确率：抽查 20 条行为变化，误报 < 10% | **必须在非作者仓库**上测：不同语言/框架、含 feature flag 与运行时配置、至少 1 个 DB migration。判定人不参与开发、不看 AI 输出，独立对照代码与运行现象 | 中 |
| 2 | 召回率（新增）：人工预标 15 个真实行为变化，报出 ≥ 80% | 其中含 5 个跨文件/跨配置变化、2 个纯运行时开关导致的变化 | **最高** |
| 3 | 工时：发布说明撰写耗时下降 ≥ 30% | 同时记录「人工修正条数」——否则省时可能来自没人细看 | 中 |

补强理由：

- **循环验证**：自家 dogfooding 仓库 + 修复刚部署 + 自己人抽查，三者叠加时「误报接近 0」不可外推。GLM 认为第一个数字大概率已达标，这个判断本身正说明指标太容易通过。
- **漏报比误报致命**：定位是回归辅助，QA 少测一个场景就是线上事故。只测精确率会让「少报」显得完美——一个永远只报 1 条的系统精确率 100%，召回率 7%。
- **退出条件**：任一指标不达标即不续。另加定性闸门——试点期间若出现 1 次「按 CoDelphi 结论放行、实际行为不符」，直接终止，不进入指标讨论。
- 对外模板需注明基线数据来源、判定人身份与仓库特征，否则客户无法复用。

## 6. 方法论提醒：评审收敛不等于独立验证

GLM 把「三份外部评审 + 自家四角色评测都指向 CTO 最弱」当作真实缺口的独立印证，这里需要打折：

- 三份评审大概率读同一份官网/README、由同类模型、收同类角色提示生成，收敛可能来自**输入趋同**，不是交叉验证。
- 自家四角色评测若共用评分维度，更接近「同一把尺子量四次」。
- 「CTO 最弱」应记为**强信号、非定论**。真正的独立验证是 §4 的第三方仓库盲评，以及第一个付费客户的第一轮采购提问。

建议后续评审刻意给不同模型**不同输入集**（一份只给首页、一份只给 `spec.json`、一份只给运行中的产品），看结论是否仍收敛。仍收敛才叫独立。

## 7. 我仍然坚持的一句

「代码发生了什么」与「做对了没有」之间隔着的不是话术，是判据。短期不造判据是对的；但定位要退到**连「行为账本」都不暗示观测真实性**的那一格，否则下一轮评审会打同一堵墙的第二层。停止暗示，把「翻译」价值做深——这个结论我完全同意，只是它比 GLM 说的还要再退半步。
