# CoDelphi 分析管线与提取策略（2026-11-10）

> 本文描述生产在跑的分析管线全貌与每一层的策略依据。能力状态以代码与基线文档对账为准（`specsight-gap-improvement-plan.md` 为改进工单簿）。superset 盲评四跑实测数据见 `pilot-blind-eval-superset-rerun-2026-11-10.md`（预标冻结件与判定口径见该报告 §1-§2）。
>
> 修订：2026-11-10 v2（外部评审采纳，含 P0 修正与可观测补齐）：「diff 必选」明确为**优先选择而非无条件全覆盖**，覆盖率回执新增 diff 面入选/遗漏计数（migration 058）；行为枚举容量上限与完整性状态显式披露；空结果三态区分（无变化/候选全被清洗/提取为空）；full 定义澄清；盲评结论加样本口径限定；行为等价去重规则成文；M9 一致率分母警示。

## 0. 一页总览

```
触发（push / daily / push_count / manual）
  → 入队 + 额度预留（billing gate，拒绝留 queued 自动补区间）
  → 变更上下文（diff patch） + 上一版规格（措辞锚定 + 功能名清单）
  → 模式判定（增量 / RC2-carry / 全量，保守回退）
  → 分区装配（diff 文件必选 + BFS 信号遍历 ×6 分区）        ← W0-7
  → 逐趟提取（每趟允许集清洗 + 硬失败重试一次）
  → 行为面枚举（patch-scan 行为文件 → 分组 → 复述/判定两步提取）  ← W0-8/W0-9
  → 确定性合并（行为等价去重 + changes 截断 150 + 功能名排序）
  → 证据清洗（不可溯源声明剔除，warn 留痕）
  → 一致性核验（同功能互斥结果并存告警）                    ← W0-9
  → 落库（spec_version append-only + 坍缩护栏 + 回归任务）
  → 结算（1 SAU/run）+ 通知 + M9 影子对比（增量 run）
```

superset 盲评同窗口四跑：召回 46.7% → 53.3%（W0-6 多趟）→ 80.0%（W0-7 diff 必选）→ 86.7%（W0-8/W0-9 行为面枚举 + 复述/判定分离）。

## 1. 触发与入队

| 触发 | 行为 | 依据 |
|---|---|---|
| push（webhook 签名） | 按仓库 `analysis_trigger` 模式：push=立即；push_count=计数达 N 触发；daily=低峰小时兜底（`analysis_trigger_hour`，默认 3 点） | 定价校准：1 push = 1 SAU 让高频直推用户必然超额 |
| manual（产品页） | `queueAnalysis(repoId, null, HEAD)` | beforeSha 空由管线解析水位 |
| 兜底 sweep | queued-run-recovery 每 60s 领取超 10 分钟无人认领的 queued（每仓库仅最新，旧标 superseded）；analysis-trigger 每小时对 daily/push_count 且有积压的仓库补一次 | after() 秒级派发是常态，超时即孤儿 |

入队走 `enqueueRunWithReservation`：额度预留 → 执行 → `capture` 结算（`FIRST_RUN_UNITS = 1` SAU/run，与趟数无关；各趟成本按 `llm_call_receipts` 如实记账，W0-5 三方可对账）。闸门拒绝（quota_exceeded 等）→ run 留 queued 不标 failed，条件恢复后自动补跑。

## 2. 模式判定（保守回退链）

```
incremental 请求 → 全部满足才走增量：
  有上一版规格 ∧ diff ≤ 200 文件 ∧ 受影响集非空 ∧ 受影响占比 ≤ 60%
任一不满足 → full，但 previousFeatureNames > 0 时走 RC2-carry：
  按行为变更集（patch-scan 只认实现级文件的代码行变更）重算受影响面
  → 命中既有功能 → incremental-carry（carry-forward 沿用未受影响功能）
  → 未命中（索引未覆盖的新功能）→ 保持 full（需要 AI 看新代码）
```

红线（§specsight-gap 计划）：规格完整性不因运行模式降级——W0-6 起增量/RC2-carry/全量共用同一分区提取层，模式只影响投入方式。superset 盲评窗口（131 文件，与 v40 索引零交集）按此策略合法地解析为 full。

**full 的定义澄清**：full = 全量分析策略（不依据上一版缩小范围），**不代表仓库所有实现文件均被读取或全部行为均被覆盖**——实际覆盖范围以本次 run 的 coverage receipt 为准（§3/§8）。禁止把 full 误解为全仓库扫描。

## 3. 分区装配（W0-7 diff 必选）

`getPartitionedAnalysisSources`：同一远程索引上反复规划，每趟排除此前已选路径，直至无新路径或 6 分区触顶（`ANALYSIS_MAX_PARTITIONS`）。

每分区预算（`analysisSliceBudgets`）：80 文件 / 600 行区间 / 160KB 内容 / 单文件 ≤600 行。

**选择顺序（每个分区）**：

1. **diff 文件优先（W0-7，2026-11-10 评审措辞修正）**：窗口 diff 的全部路径按路径序**优先**入选——跳过噪声分类与子树份额（被本窗口修改本身就是入选理由），仍尊重每分区预算（80 文件 / 600 行区间 / 160KB）。
   - **精确语义**：diff 路径在分区 N 装不下的，会在分区 N+1 的必选阶段**续装**（每分区预算独立重置，`excludePaths` 只排除已入选路径）——不是「跳过即永久丢失」。
   - **但 6 分区是硬上限**：分区耗尽后剩余 diff 路径被丢弃且**必须可见**——覆盖率回执新增 `diff_total_paths / diff_selected_paths / diff_omitted_paths`（migration 058），遗漏不可静默。
   - 因此准确表述是「**diff 优先 + 尽量全覆盖，帽下部分覆盖可观测**」，而非无条件全覆盖。
   - diff 文件含测试/文档/CI（被本窗口修改即入选）；它们占用预算会相应减少实现面装配量（B1 口径分列：impl 装配与 diff 覆盖是两个独立指标）。
2. **BFS 信号遍历**：scope roots 广度优先（顶层公平于深层），噪声目录整树跳过（tests/docs/examples/bench/隐藏目录），文件级噪声分类排除（decoy 命名防不住，策略只回答「不看什么」），entrypoint 信号模式定优先序；多子树竞争时单子树份额 ≤50%。

分区切分由 `excludePaths` 驱动：跨分区稳定（路径序），互不重叠。装配结果经 `sliceToSourceFiles` 硬顶裁剪（超预算整文件排除），**真实窗口以裁剪后为准**——assertEvidence/清洗的允许集来自它，不来自规划面。

**覆盖披露（B1）**：每次成功 run 落 `analysis_coverage_receipts`（装配/全实现面文件数与字节、覆盖率、分区数、触顶标志，**2026-11-10 起 + diff 面入选/遗漏计数**，migration 058）。触顶显式警示。**实现面装配率与 diff 覆盖率分列披露**（superset 实测：2149 实现文件装配 35 个 = 1.15%；diff 面以 W0-7 起必选口径另计）——两者不可混用。

## 4. 逐趟提取与韧性层

每趟 = `analyzeWithAI`（分区代码 + diff patch + 措辞锚定 + 增量范围约束 + 分区 i/N）→ zod 解析 → 证据清洗。

**措辞锚定（P0）**：上一版场景全文喂入（24KB 帽），行为未变的场景与功能简介必须逐字沿用——消除逐次重提取的改写噪音（superset 盲评的 L1/L13 命中质量受益于此）。

**韧性层（2026-11-10 生产事故族推动，全部有回归测试）**：

| 故障类 | 机制 | 事故来源 |
|---|---|---|
| 场景结果键漂移（模型把「结果」直译为 result 键） | 解析层别名升格 outcome（显式 outcome 优先） | run 174–179 全量 6 连挂 |
| 证据路径带零宽字符 | 解析层清洗不可见字符（U+200B 等） | W0-2 重跑误杀合法 diff 路径 |
| 引用「真实存在但本趟未读」的文件 | sanitizeEvidence：不可溯源声明剔除 + warn 留痕（红线不变：进规格的事实必须可溯源）；**清洗粒度为逐场景/逐变化独立判定**——同一功能下证据无效的场景被剔除时，同功能证据有效的场景不受影响；功能的全部场景被剔除才剔功能（无父子级联放大）。清洗后为空按「无行为变化窗口」接受，**但候选存在而全部被清洗时发独立告警 `all_candidates_rejected`**（空结果三态：无变化 / 候选全被清洗 / 提取为空——后两者不得伪装成前者） | run 185/186 |
| 单趟硬失败（解析/网络/网关） | 重试一次（双份 receipt 如实记账），两次都失败才 run 失败；超时经 AbortSignal 取消在途请求 | — |

清洗后为空 = 本趟无行为变化窗口，按既有语义接受（空版本由坍缩护栏下游告警），不在此处抛错。

## 5. 行为面枚举（W0-8/W0-9 两步提取）

分区提取覆盖「实现面」，但自由阅读的注意力会偏向大而显著的行为，小而深的边缘行为被泛化吞掉（W0-7 后残余 L8/L15 实测：文件已读、行为未写）。W0-8/W0-9 把召回从注意力问题变枚举问题：

1. **枚举**：`behavioralChangePaths`（patch-scan：实现级文件 + 代码行变更判定，注释/空白变更不算，保守方向宁算行为）给出行为文件清单
2. **分组**：每组 ≤6 文件、≤8 组（`BEHAVIORAL_ENUM_GROUP_SIZE` / `_MAX_GROUPS`），路径序稳定分片
3. **两步提取（每组 2 次调用）**：
   - **复述步**：逐变更块只复述改前/改后——机械任务不做显著性判断（`@@` 头解析 → hunk ±30 行上下文读取，单文件 400 行帽）
   - **判定步**：对每条复述显式分类。判定偏向计入：**只有能明确断言对外部观察者完全不可见才跳过；拿不准 → 一律输出（宁可多写一条，不可漏写一条）**；判为内部实现 → changes 里 kind=reviewed 留痕（完整性声明，宽松模式教训：错漏真行为 > 多留一条边缘条目）
（枚举产出与分区趟走同一 mergeChunkResults / zod / sanitize 管线合并，行为等价去重吸收重复；组硬失败重试一次，仍失败跳过该组——枚举是增强层，不阻塞主提取；定向解析为宽容 schema：product/release 缺省注入占位——合并层只取分区首趟，占位不进规格，features 允许空）

**容量上限与完整性状态（2026-11-10 评审采纳，必须与主提取覆盖率分开报告）**：

- 枚举容量 = 每组 6 文件 × 8 组 = **每 run 最多 48 个行为文件**；超出部分不进入枚举（日志 + 指标可见）
- 单文件变更区上下文帽 400 行：hunk 按行序读取、预算耗尽后的后续 hunk 不再读取（已知的采样式缺口，改进方向 = hunk 级公平预算；截断事实随指标披露）
- 每次 run 输出结构化指标：`behavioral_paths_total / paths_enumerated / paths_omitted / groups_total / groups_completed / groups_failed / status`
- status 取值：`complete`（全部行为文件枚举成功）/ `partial`（有组失败或组帽截断或文件遗漏）/ `failed`（无一文件枚举成功）/ `not_applicable`（无行为文件）——**枚举 partial 时 run 仍为成功，但完整性状态不得被误读为完整成功**

设计依据：单步提取把「复述变更」与「判断显著性」混在一次注意力里，显著性过滤静默吞掉低显著行为——四跑递进的最后一级（80.0 → 86.7）即来自把两件事拆开。prompt 含控制流语义提示（try/except(pass) 被捕获的错误不写成输出行为——L12 反向场景教训）。

## 6. 确定性合并与一致性核验

`mergeChunkResults`（无 AI 通道）：功能按 stable key 分组、场景按行为等价去重、引用冲突前缀重编号、changes 去重后截断 150（截断必日志可查）；每趟结果已在提取层过 zod，合并有意绕过 ≤50 功能/≤40 场景上限。

**行为等价去重的精确规则**（`scenarioBehaviorEqual`，非文本相似度）：category 相同 ∧ context/action/outcome 三字段逐一 `specTextEquivalent`（NFKC 归一 + 空白折叠 + token 签名一致 + **否定计数一致**）——即「同一触发条件、同一前置、同一可观察结果、且肯定/否定语气一致」才算等价；仅措辞不同可合并，任何字段语义差异（同触发不同结果、同结果不同触发、肯定/否定翻转）不可合并。

**changes 截断 150 的作用范围**：changes 是发布变化清单的展示层（changelog）；功能与场景落库不受该截断影响，回归任务由功能/场景生成（与 changes 无关）。截断只意味着发布页 changelog 不展示第 151 条起的条目，事实以日志 `changes truncated {before, after, dropped}` 留痕（`changes_truncated` 计数进入完整性账本为 P1 项）。

**一致性核验（W0-9）**：同功能内同一错误/状态码 token 被「不再」紧邻否定与被肯定陈述并存 → 冲突对告警（枚举多通道产物的语义矛盾，如「不再返回 422」与「返回 MissingOAuth2TokenError」并存）。否定判定要求紧邻无句读（「不再重试，直接返回 504」不误报）。落库后告警不改写——人工核实签发是产品定位。

## 7. 落库、结算与观测

- `insertSpecVersion`（append-only）：工作台 upsert 集 == 版本层合并集（W0-3 常驻回归锁定）；坍缩护栏（场景数骤降 >30%）只告警不阻断
- 回归任务：从行为变化自动生成场景级回归任务（P0）
- 结算：`capture` 每 run 1 SAU；结算失败只告警，sweep 恢复（D15：结算不改写分析状态）
- 通知：分析完成 / 坍缩告警 / 额度事件，best-effort 投递
- M9 影子对比：增量 run 落库后另取单窗切片跑全量提取，只对比不落库。**口径警示：≥98% 一致率只作为两种执行路径（增量 vs 单窗）的一致性指标，不是分析管线真实召回率的证明**——两条路径共用同一模型/prompt/索引，错误高度相关；且一致率分母必须定义（双方共同漏掉的行为不在分母内）。影子对比不能替代人工盲评

## 8. 边界（诚实披露）

1. **静态不可见**：部署期 feature flag 翻转、运行时配置、数据依赖行为——静态提取原理性不可见（盲评盲区样本结构性 0/2），已在 `/data-notice`（app/data-notice 页）声明；**动态行为的人工补充入口 = 规格编辑器（人工核实/编辑场景）+ 反馈通道**，未来可在 B1 页面显式指引
2. **触顶预算**：超大仓库（实现面 2149 文件量级）6 分区装配率 ~1%，覆盖率数字如实呈现（B1），不作为门槛解释理由
3. **判定分歧**：低显著度行为（访客跳过重试、脱敏跳空值）在提取模型重要性先验下可被判「内部实现」——枚举保证显式回答，判断分歧走人工核实签发与更强模型重试
4. **spec 内部矛盾**：枚举多通道产出可能语义矛盾并存——一致性核验为**局部语义矛盾检测**（同功能同错误 token 的否定/肯定并存），不覆盖跨场景逻辑矛盾、前置条件差异型归并错误、功能简介与场景冲突——自动消解未做，检出即转人工核实

## 9. 分析完整性账本（R1，2026-11-10 落地）

run 级六维度完整性状态，落 `analysis_completeness_ledger`（run 唯一，details JSON 含全部计数），best-effort 写入（失败只告警）：

| 维度 | 状态来源 | 典型 partial 原因 |
|---|---|---|
| sourceCoverage | 覆盖率回执（impl 装配 + diff 入选/遗漏） | 分区触顶 / diff 路径遗漏 |
| behavioralEnumeration | 枚举指标（paths_total/enumerated/omitted、groups 完成失败） | 组帽截断 / 组失败 |
| extractionCompletion | 分区趟数 / 重试 / 空结果趟 | 重试发生 / 无行为变化趟 |
| evidenceIntegrity | sanitize 剔除计数 + all_candidates_rejected | 有剔除 / 候选全被拒 |
| mergeIntegrity | changes 截断 / 场景去重 / 一致性冲突 / 坍缩 | 截断 / 冲突 / 坍缩 |
| verification | 一致性冲突 + M9 影子 | 冲突 / 影子不一致（人工核实在外部生命周期） |

整体状态 = 最差维度（禁止单一百分比）。**分析成功 ≠ 完整 ≠ 正确**。

superset 实测（run 63）：sourceCoverage partial（35/2149，diff 57/120 入选 63 遗漏）、behavioralEnumeration partial（47/57，8/10 组）、extraction complete（6 趟零重试）、evidence complete（零剔除）、merge partial（去重 674、一致性冲突 1）、verification partial（1 冲突）→ **overall partial**。账本一行回答「完成了什么、没完成什么」。

## 10. 运维旋钮

| 环境变量 | 默认 | 作用 |
|---|---|---|
| `ANALYSIS_MAX_PARTITIONS` | 6 | 分区数上限 |
| `BEHAVIORAL_ENUMERATION` | true（"false" 关） | 行为面枚举开关 |
| `BEHAVIORAL_ENUM_GROUP_SIZE` | 6 | 每组文件数 |
| `BEHAVIORAL_ENUM_MAX_GROUPS` | 8 | 枚举组数帽 |
| `INCREMENTAL_SHADOW` | false（生产已开启） | M9 影子对比（增量 run 落库后另跑一次单窗全量，只对比不落库） |
| `AI_TIMEOUT_MS` | 180000 | 单次网关超时 |
| `PR_PREVIEW_ENABLED` | true | PR 预演 |
| `LLM_PRICES` | 生产已配置（deepseek-flash 高峰/错峰两档，USD） | LLM 调用成本核算——缺失时回执成本 NULL（未定价 ≠ 零成本） |

**成本特征**：一次 run 的 LLM 调用数 C = 分区趟数 P（≤6）+ 枚举组 G（≤8）×2（复述+判定）+ 影子 S（增量 1，生产已开）+ 重试 R——极端仓库满载 23 次基础调用。**1 SAU/run 是「按分析任务收费」的产品定价（用户购买的是一次分析任务）；计费稳定 ≠ 单位经济稳定**：不同仓库规模的单 run 成本差异不可控，须建立成本观测（每 run 总 token、实际成本、按仓库规模的 P50/P95/P99、枚举增量成本、影子成本、单 SAU 毛利分布——P1 项）。影子分析应视为独立质量验证成本，具备采样率/规模门槛/退出条件。

**计价口径（2026-11-10 配置）**：`LLM_PRICES` 按 deepseek-flash 官方两档配置（USD/百万 token）：高峰（UTC 周一至周五 01:00-04:00、06:00-10:00，即北京工作日 09:00-12:00、14:00-18:00）输入命中 $0.006 / 未命中 $0.30 / 输出 $1.20；错峰（其余时段含周末）全部半价。**缓存命中按 cache 价替代 input 价计费（DeepSeek 语义，勿叠加）**。档位写入 pricing_version 后缀（:peak/:offPeak）供审计；中国法定节假日官方按错峰但未内置日历，节假日白天成本会偏高（宁高勿低）。superset 实测（缓存命中 ~90%）单 run 成本 ≈ $0.07–0.19（¥0.49–1.35），对照 1 SAU = ¥0.99：打平或微利，按 R5 两周数据复核。

**手动补跑路径**（无 push 场景）：服务器 `tsx` 脚本 `queueAnalysis` + 原子认领（`UPDATE started_at WHERE queued AND started_at IS NULL`）+ `await runAnalysis(id)`；sweep 只领 >10 分钟的 queued。
