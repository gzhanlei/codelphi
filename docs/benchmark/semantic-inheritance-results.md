## 1. 实验口径

- A（full_rebuild）：读取目标版本中当前及前序窗口的全部冻结证据源码。
- B（diff_only）：只读取当前窗口变更的非生成资源源码，不注入上一版规格。
- C（semantic_inheritance）：读取与 A 相同的源码，并注入 baseSha 规格与相关功能范围。
- 基线由同一提取管线在隔离目录生成；连续链的下一窗口复用上一窗口 C 输出，不读取生产 active spec。
- 共用 `analyzeWithAI`、ds-flash、temperature=0、相同结构化输出契约。生成资源和 `git-tree` 元数据被排除。
- 指标：`featureName + reference` 精确身份，分别报告逐字保留、缺失、新增及同 reference 内容重写。**逐字保留不是语义正确性的完整判据。**

共完成 **32 次真实模型调用、3,983,386 tokens、累计模型耗时 551,522 ms**。随后使用原模型输出做离线复核回放，新增模型调用为 **0**。生产写入为 0。token 不是全仓成本或费用结论，各臂输入范围不同，不能据此直接比较单位成本。

## 3. 正反证据

### 3.1 文本锚定对旧认知连续性有效

C 在 8 个窗口完整保留全部旧场景；CH-002 保留 56 条非 Turnstile 旧场景。特别是：

- TF-002 没有制造产品行为变化；
- TF-003 只新增两个恢复场景；
- CD-001 保留既有 25 个场景，并新增 hunk 保真功能；
- SB-002 保留既有助手场景，同时新增独立 Web 链接化功能。

这支持“上一版结构化理解可以成为下一次分析起点”，但当前机制主要是**文本锚与既有引用继承**，还不是已证明的稳定行为身份系统。

### 3.2 新行为发现是独立短板

两个窗口出现同一类缺口：

- CH-001 的“双配置为空关闭 / 只配其一拒绝启动”进入 `changes.reviewed`，但未形成当前配置场景。
- SB-003 的 Mobile 链接化进入 `changes.reviewed`，但当前规格只保留 Web 场景；A 与 B 都捕获了 Mobile 行为。

因此，`reviewed` 候选与当前行为规格之间必须有明确的提升、保留未决或拒绝流程。只在发布元数据中提到新行为，不等于团队当前认知已经包含它。

**离线复核已补上保守门禁**：没有任何当前场景证据路径覆盖的 `reviewed` 新行为会进入 `review_queue.json` 的 `newBehaviorCandidates`，运行状态改为 `review_required`，不再静默标记 `succeeded`。原始模型输出保留为 `semantic_inheritance.raw.json`。

随后按冻结预标与代码证据执行了 AI 预标裁决：SB-003 提升 4 个 Mobile 场景，CH-001 提升 Web 与 2 个配置场景，TF-002 驳回测试基础设施候选，CH-002 以新 `EC-4` 记录 partner 既有行为。**8 个新增场景全部保持 `unverified`，没有因为裁决而变成测试或人工已验证。**各窗口 `review_decisions.json` 与 `verification.json` 保留完整依据。

### 3.3 reference 不是可靠行为身份

CH-002 的原始输出中，C 正确移除了全部 Turnstile 当前场景，但把原“缓冲期放行”的 `EC-2` 改为“partner 免 email_code”。这是同 reference、不同业务的身份碰撞。离线复核先将该场景从当前 C 规格移入 `identityCollisions`，再以新 `EC-4` 记录 partner 既有行为；旧缓冲期身份没有被覆盖，新场景保持未核实。

该案例证明：

- `missing=0`、`new=0` 仍可能隐藏身份漂移；
- 必须单独检测同 reference 内容重写；
- 稳定内部 `behaviorId`、前后关系和人工裁决不能由 HP/EC/ER 编号代替。

### 3.4 A/B 与 C 具有互补性

B 没有旧语义基线，容易产生身份分裂和测试文档驱动的功能集合，但 SB-003 中 B 发现了 C 漏掉的 Mobile 新行为。A 也能提供新行为覆盖，却伴随大量重写。

下一轮不能只优化锚定保留率，应组合：

1. C 的既有行为连续性；
2. B/独立发现通道的新行为召回；
3. 同 reference 碰撞与平台身份校验；
4. 对未提升、未覆盖和无法判断的显式披露。

## 4. 本实验没有证明的事项

- 没有使用生产人工修正、`verified_at` 或真实测试执行状态，**未验证生产核实记录的安全继承**；仅以合成夹具验证 unchanged / behavior_changed / new / identity_collision / tree_revert 的迁移规则。
- 没有全仓重建，不支持全产品召回率、全仓成本或生产 SAU 结论。
- 每个窗口只运行一次，不支持跨模型、重复运行或普遍统计结论。
- 没有真实设备、浏览器、外部服务或生产配置验证。
- 没有独立领域专家盲评；当前是 AI 静态预标与确定性指标口径。
- CH-002 的相同 tree 只证明代码内容一致，不证明部署配置或运行时状态一致。
