## 4. 实验输入隔离

1. 每个窗口只能使用 base/target 当时可用的信息；禁止读取 target 之后的代码、文档、事故复盘和本目录之外的答案材料。
2. 基线必须使用 baseSha 对应的历史规格版本，或仅由 baseSha 重建；不得使用当前 active production spec。
3. 历史人工修正与核实状态无法恢复时标为 missing，不得从当前生产状态倒填。
4. commit message 是 `declaredIntent`，不是行为真值。若作为分析输入，A/B/C 三组必须获得完全相同的文本。
5. 三组使用相同的分析代码版本、模型配置、Prompt、预算、输出语言和缓存条件；差异只能是基线继承机制。
6. 在 scratch 环境运行，不写生产规格、不触发生产分析；保存输入、输出、配置与代码哈希。
7. 标注人员与运行人员可以相同，但最终输出评审必须隐藏 A/B/C 来源；领域专家复核完成前，结果只能称 AI 预标口径。

## 5. 判定口径

按窗口分别报告，不用大量简单场景稀释困难案例：

- **身份关系**：新增、修改、移除、扩展、平台关联、恢复是否命中；不确定但如实标 unknown 与错误确定关系分开。
- **未变保持**：`unchanged` 中的行为是否被错误删除、重写为行为变化或复制成并列身份。
- **证据适用性**：证据是否绑定正确版本；行号重映射、生成资源与平台证据是否被错误解释。
- **核实继承**：历史记录是否保留，当前有效性是否重新推导；旧 commit、旧平台或旧场景的核实不得自动迁移。
- **纠错能力**：后续人工修正是否成为下一次分析输入，而非被旧 AI 结论覆盖。
- **成本**：模型调用、token、耗时和人工裁决分钟分别记录，不合并成单一分数。

高严重度错误单列，不能被平均准确率抵消：

1. 把旧核实或旧平台验证错误继承为当前有效；
2. 把明确未变行为报成删除，或把明确变化报成未变；
3. 把可能关系伪装成确定身份合并/拆分；
4. 把目标之后的信息泄漏进分析或答案；
5. 把测试、文档或构建产物变化直接当成产品行为变化。
